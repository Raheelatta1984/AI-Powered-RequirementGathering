# Reading `readthis.md`: v11 → v12

## What the source actually contains

`readthis.md` is a 1,847-line combined implementation guide, generic specification, and quick-reference card for a proposed v11 standalone HTML tool. It describes ten-phase elicitation, isolated SME sessions, pause/resume, voice, IndexedDB, scope/priority flags, cross-SME comparison, exports, and mandatory BA review.

The checked-in repository did **not** contain the referenced HTML, separate specification file, Windows batch script, or working application. Claims such as “production ready,” tested performance, automatic filesystem saving, and GDPR compliance were source-document claims, not verifiable properties of code in this repository. V12 does not repeat them as established facts.

## Preserved intent

- BA-led, plain-language elicitation rather than an unstructured chatbot.
- One question at a time, role-aware context, editable suggestions, explicit unknown/skip controls.
- Ten phases, forward progress, targeted follow-ups, and a maximum of five ordinary questions per phase.
- Individual stakeholder sessions, pause/resume, original-answer retention, scope flags, and MoSCoW priorities.
- Human review before a build handoff; no silent conversion of uncertainty into fact.
- Optional browser voice input/read-aloud and English outputs.

## Contradictions and corrections resolved

1. **Five questions per requirement vs per phase:** V12 uses three core questions plus up to two follow-ups per phase. BA-requested reopen questions are additional, explicit audit events.
2. **“No PRD/risk assessment” vs the requested build handoff:** V12 generates a reviewed requirements/solution handoff, not a final PRD or release approval. Technical/cyber content is proposed planning material requiring specialist validation.
3. **Automatic Windows filesystem saving:** a normal web page cannot silently write to `C:\...`. V12 saves to its server data directory and offers explicit downloads/calendar imports. No administrator batch script or registry modification is required.
4. **Browser-specific resume:** V12 checkpoints are server-side; the private link can resume from another browser. The link is a bearer credential and must be protected.
5. **“Zero data sent externally” while using Claude/browser speech:** V12 explicitly discloses optional provider and browser-vendor processing.
6. **Guaranteed personas/languages:** browser voices vary by device. V12 exposes available voices and AU/GB/US English accents rather than guaranteeing six named voices or translation quality.
7. **Unique session ID as access control:** V12 uses separate high-entropy, expiring, rotatable invite tokens and stores only hashes.
8. **Production/compliance claims:** replaced with a concrete deployment checklist and explicit limitations.

## Not carried forward as working features

- The missing v11 HTML and batch files are not fabricated or reconstructed byte-for-byte.
- No automatic Outlook email, SharePoint upload, external calendar reservation, or live simultaneous interview room.
- No DOCX/PDF application export or binary attachment parsing. The requested deliverable is Markdown; text evidence notes are supported.
- No indefinite-retention promise, automatic local-disk encryption, or compliance certification.
- No automatic code generation/deployment. The handoff is intended for a separately controlled AI builder.

The original `readthis.md` remains unchanged as historical source material. This document and the running code define V12 behaviour.
